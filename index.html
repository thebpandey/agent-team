A clear route from request to release.

Agent-Team admits safe work, keeps each writer inside an owned worktree, sends the exact candidate to an independent reviewer, and integrates only revision-bound CLEAN results. A finding returns to its lane without resetting unrelated work.

Release remains separate from integration. Missing authority, evidence, or recovery facts hold the affected action; they are never guessed through.

01

One task authority

After an approved v8 cutover, Beads is live and TASKS.md is legacy provenance. Use task add for queue changes or one-off for one bounded ad-hoc objective.

02

Independent lanes

The orchestrator coordinates; bounded developers write; non-author reviewers return FIX or CLEAN. Path conflicts and blockers stay scoped to the lane they affect.

03

Durable evidence

Checks, review, gate, integration, and release each bind their exact revision. Serial integration and transactional lifecycle records keep recovery explicit.

Foreground control without fragile session memory.

Use status to inspect, pause to hold admission, stop to end a foreground turn, cancel to end scoped work, and resume to reconcile Git, tracker, receipts, resources, and pending operations before continuing.

Compact handoff

Each active run derives one bounded Markdown handoff from canonical receipts and checkpoints: current tasks, revisions, verdicts, evidence, blockers, prohibitions, resources, and the next action.

Resources on demand

A project may use at most two Agent-Team-managed development servers and two browser sessions. Each is bound to a team, worktree, revision, purpose, and evidence; unknown processes are never killed by port or PID alone.

Readable projections, not competing stores

BLOCKERS.md projects active root blockers and drops resolved entries while durable evidence remains. DECISIONS.md records consequential product, security, and authority choices; routine failures stay with their task and receipt history.

Continue in Codex or Claude Code.

Open the same canonical Git project in either host. The tracker, run, claims, evidence, blockers, and handoff remain project records; switching the foreground host transfers no lease and requires no old session to return. Do not run both host harnesses on the same project at once.

Codex

Use $agent-team status or $agent-team resume. The native adapter supplies Codex delegation context without changing the project authority model.

Claude Code

Use /agent-team status or /agent-team resume. The same binary actions and project records drive the continuation.

One-time legacy fallback

External Ed25519 trust is not part of normal v8 setup or use. It is required only when a stale or unverifiable v7 project lacks a current canonical approval. The read-only prepare flow inventories exact project, evidence, remote, and host state for a short-lived operator-signed approval; it never self-grants authority.

Install once, then set up the project.

Use a checksum-verified v8 package and select Codex, Claude Code, or both. The native installer owns only its recorded binary, contract, entrypoints, and manifest; it does not register hooks or MCP servers or rewrite unrelated host settings. If an older same-name skill is still discoverable, installation or update stops and reports its path. Preserve it in a backup outside skill discovery, then retry. Native status uses the installed native entrypoint version.

Windows amd64

Download the Windows bundle and its SHA-256 sidecar. Verify the hash in PowerShell, extract once, and open the extracted folder. WSL is not required.

.\agent-teamctl.exe install --host both --json

Use codex or claude instead of both for one host. Exact verification and installation commands.

Linux amd64

Download the Linux archive plus RELEASE.json, SBOM.cdx.json, and SHA256SUMS from the same release into an empty folder. Run sha256sum -c SHA256SUMS, then extract the archive into that folder.

./agent-teamctl install --host both --json

The strict Linux package contract is preserved. macOS source checks do not mean a macOS binary is published.

The dashboard is an ignored, read-only local snapshot. It is not a server, task store, release record, or visual-review evidence.

For a new product or major replan, Project Kickoff can produce the optional first-run artifacts and approved Agent-Team handoff before setup.

LeanCTX, read-only Serena, code-only Graphify, and Playwright are preferred only when the task benefits from them. Visual work uses Impeccable plus UI/UX Pro Max. These task-scoped capabilities never widen authority; native Git, Go, search, and file operations remain the fallback.
