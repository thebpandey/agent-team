# Canonical documentation implementation brief

## Scope and sequencing

Implement Task 5 of the approved LANES-PLAN only after the parent releases shared code path consumers. Work in the feature worktree. Keep current Pro canonical Markdown basenames uppercase in recognizable existing directories. Do not alter Lite, historical archives, persisted project evidence paths, native role IDs, or unrelated user content. Read the approved design and applicable skill instructions completely before edits.

## Protocol ownership

Make references/LANES.md the single detailed lane protocol. Other references link to it and describe their own integration boundary without duplicating field definitions. Ship BRIEF.md, NEXT-TASK.md, and HANDOVER.md templates under assets/templates/lanes. Canonical runtime lane documents use uppercase basenames, preserving previously persisted lowercase paths on recovery.

Cover ordered queues, disjoint writable paths, one retained worker and worktree per lane, per-task claims and commits, serial accepted integration, rotation and authentic liveness, fact-sheet ownership and expiry, reviewer independence, verifier-first gates, bounded updates, immutable assignments, decision IDs and reversals, and a recorded outcome or UNKNOWN for every actual dispatch. Packet preparation is not dispatch proof. Unknown liveness never frees a slot. Rotation alone never proves a writer stopped.

## Lean operation without weaker evidence

Document next-task packets targeting fewer than 400 tokens, handovers targeting fewer than 500 words, enforced brief word and update character limits, and paths instead of content dumps. Full logs remain retained separately. State exact enforcement limits where a native message or opaque shell write cannot be inspected. Do not claim universal interception.

Document the configured heartbeat as fallback, notifications as normal wake signals, and no sleep-and-check loops. No process, daemon, scheduled activity, or work after the host turn ends is introduced. A host wait-duration limit may require earlier return; do not manufacture a status poll merely because the wait returned. Lower heartbeat intervals cost more orchestrator turns and do not inherently create progress.

Preserve quality-first model routing and independence. A skill cannot change its parent model. Explain execution-session versus planning-session model selection in terms of the actual host catalog. Do not invent a cross-vendor ordered tier comparison or silently substitute a weaker reviewer. Above-Opus recommendations require a real comparable detected model; unknown comparisons remain unknown.

Explain owner-approved context reduction, exact selected settings, reversible receipts, drift refusal, helpers installation and self-checks, bounded single-record reads, and one session per phase using recovery-index handoffs. Distinguish configuration visibility from proof a dependency is unused. Never auto-disable tools.

All token-savings claims are estimates unless measured by usage.mjs. Describe reuse mechanisms without inventing percentages.

## Host behavior and continuity

Use actual supported retained-worker controls for each host and qualify unavailable capabilities. Codex surfaces differ: a message to an active agent and continuation of an idle retained agent are distinct. Claude support must be verified rather than assuming any subagent can receive arbitrary messages. Unsupported retention uses a documented rotation or fresh-worker fallback with complete applicable instructions.

Explain the user-approved removal of historical session UUID locking narrowly. Keep project coordination registration, audit history, registered-worker path restrictions, task authority, native workflow identity, and revision-bound gates. Explicit user-directed maintenance is not an assertion of old-worker death or native authentication and does not grant release approval.
