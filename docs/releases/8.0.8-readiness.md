# Agent-Team 8.0.8 release readiness

Version 8.0.8 permits the closed legacy Beads authority during native v8 cutover. Linux amd64 and Windows amd64 remain the only published native downloads.

## Migration contract

- The repository root and native Codex and Claude entrypoints all declare version 8.0.8.
- A legacy project with `tracker.kind: "beads"` keeps its existing `.beads` tree in place. Prepare, cutover, and rollback write only separate v8 authority or prepared-request artifacts; they do not convert, delete, rewrite, or re-home Beads files.
- The tracker export still proves the selected scope is closed. Unsupported legacy tracker kinds remain rejected.
- Historical Node package v7.3.1 materials remain historical. Its manifest, archive metadata, and archive name stay at 7.3.1 and do not define the active root-skill version.

## Publication gates

1. Run `go test ./... -count=1` and `go vet ./...` on Linux, macOS, and Windows.
2. Package with `go run ./cmd/vnext-release package --version 8.0.8 --commit "${GITHUB_SHA}"`; verify Linux canonical assets and the Windows bundle, manifests, SBOMs, checksums, allowlist, and deterministic bytes.
3. Verify the legacy Beads prepare, cutover, and rollback regression preserves every `.beads` path, mode, and byte sequence.
4. Publish only after packaged canaries, rollback, provider verification, and revision-bound readiness evidence pass for the exact main commit.

This does not claim execution on a disconnected user Windows host. Native install, update, rollback, and uninstall retain their existing manifest-owned and conflict-preserving behavior.
