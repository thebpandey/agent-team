# Agent-Team 8.0.5 release readiness

Version 8.0.5 repairs native skill discovery and cross-platform verification. Both host entrypoints include a required description and place version information under metadata. Frontmatter checks exercise LF and CRLF on every platform. Installer deadline tests use a virtual clock so filesystem latency cannot consume their timeout before the intended runner call.

## Publication gates

The manual `vnext-release` workflow must pass for the exact main commit before creating the annotated `v8.0.5` tag and GitHub release. Source metadata remains a candidate until this workflow completes; this document does not substitute for its evidence.

1. Run Phase 1–5 checks and bind their records to the release revision and source digests.
2. Run `go test ./... -count=1` and `go vet ./...` on Linux, macOS, and Windows.
3. Collect native and benchmark evidence using the existing [benchmark contract](../benchmarks/vnext-optional-8.0.0.md).
4. Package with `go run ./cmd/vnext-release package --version 8.0.5 --commit "${GITHUB_SHA}"`; verify the archive, manifest, SBOM, and SHA256SUMS.
5. Run packaged Codex and Claude canaries, cutover, rollback, and provider verification; finalize and verify revision-bound readiness evidence.
6. Publish the verified artifacts under the new tag. Confirm the release identifies the main commit, the archive contains both corrected entrypoints, and its published checksums match.
7. Confirm GitHub Pages finishes building from main and serves version 8.0.5 with a working release link.

## Recovery and scope

The native runtime and worker contract are unchanged. Manifest-owned update, rollback, and uninstall retain changed or unknown user files. Existing v7 migration requirements, native host-home handling, and optional-tool limitations remain as documented for [8.0.4](8.0.4-readiness.md). Historical v7 package versions remain separate from this native release.
