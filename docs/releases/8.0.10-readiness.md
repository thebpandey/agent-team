# Agent-Team 8.0.10 release readiness

Version 8.0.10 makes the public native setup action durable. Linux amd64 and Windows amd64 remain the published native platforms. This document defines gates, not a claim that a candidate has passed them.

## Execution contract

- `agent-teamctl setup --mode plan --json` initializes exactly one existing `.beads` or `TASKS.md` tracker together with existing `DECISIONS.md` and `AGENT_TEAM_RULES.md` files.
- Setup writes the existing immutable native config and receipt binding. It does not invent a migration receipt, rewrite Beads, or treat a missing `.agent-team/v8/authority.json` as a defect in a newly initialized native project.
- Projects containing both tracker forms, missing policy files, invalid paths, or refused Project Kickoff approval fail closed without setup state.
- Settings and start continue to consume the established config/receipt binding. Legacy v7 cutover remains a separate signed migration transaction.

## Publication gates

1. Reproduce the prior no-op setup response and prove the native setup command now creates a receipt-bound project configuration.
2. Run `go test ./... -count=1` and `go vet ./...`; require the platform CI matrix on the exact candidate revision.
3. Package with `go run ./cmd/vnext-release package --version 8.0.10 --commit "${GITHUB_SHA}"` and verify deterministic Linux and Windows assets, manifests, SBOMs, and checksums.
4. Run the packaged Windows executable in the Windows canary and verify setup, settings persistence, and bounded start admission.
5. Publish only after required checks, canaries, rollback, and provider verification pass. Verify release assets and live Pages before closing the task.

No execution on the disconnected reporting Windows host is claimed. Cross-compilation and PE metadata inspection remain build checks, not Windows runtime evidence.
