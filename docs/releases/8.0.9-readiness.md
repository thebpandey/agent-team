# Agent-Team 8.0.9 release readiness

Version 8.0.9 connects supported settings persistence and bounded native start admission to an explicit Codex host handoff. Linux amd64 and Windows amd64 remain the published native platforms. This document defines gates, not a claim that a candidate has passed them.

## Execution contract

- Current root and native host skill metadata, controller version, release metadata, and current download links must all identify 8.0.9. Historical Node package v7.3.1 remains explicitly historical.
- Settings write a receipt-bound overlay only. Native setup, migration authority, legacy state, and the existing Beads tree remain unchanged. Invalid or stale-bound edits must not write.
- Default start admits at most one ready task. Admission, actual host launch, and completion are separate results. The installed Codex skill must perform the real host tool call and acknowledge its returned identity.
- Sequential work uses the existing team queue, bounded at eight tasks. Completion, a distinct independent CLEAN reviewer, and observed idle state are required before reuse. The next packet binds the same retained host identity to new bounded scope only after acknowledgement.
- Conflicting or ambiguous launch state fails closed. Matching interrupted packet and run/team projection writes are reconciled before dispatch. Cross-process task reservation uses the existing project mutation guard.

## Publication gates

1. Capture the behavioral failure and focused settings, command, admission, queue, replay, and preservation regression results.
2. Run `go test ./... -count=1` and `go vet ./...`; require the platform CI matrix and independent review of the complete exact candidate SHA.
3. Exercise a two-task isolated project through the native public commands and actual Codex spawn, completion, independent review, idle observation, and follow-up to the same handle. Callback invocation or shell arguments alone are not launch evidence.
4. Package with `go run ./cmd/vnext-release package --version 8.0.9 --commit "${GITHUB_SHA}"`. Verify the unchanged Linux canonical layout and the self-contained Windows bundle, manifests, SBOMs, allowlists, checksums, and deterministic bytes.
5. Run the actual packaged Windows executable in the Windows canary. Check persisted settings and native host-handoff output as well as installation. Record actual Codex collaboration acceptance separately.
6. Publish only after all required PR checks, packaged canaries, rollback, provider verification, and revision-bound readiness evidence pass. Verify live release assets and Pages links before closing the task.

No execution on the disconnected reporting Windows host is claimed. Cross-compilation and PE metadata inspection are cross-platform build checks, not Windows runtime execution. Native install/update/rollback/uninstall retain their existing conflict-preserving contracts.
