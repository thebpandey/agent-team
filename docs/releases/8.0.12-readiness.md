# Agent-Team 8.0.12 release readiness

Version 8.0.12 is an **unpublished candidate** repairing managed native updates.
It retains the 8.0.11 numbered role wizard, model normalization, setup,
Project Kickoff handoffs, and native host execution behavior. Linux amd64 and
Windows amd64 are package targets; macOS remains a source/runtime check target.

## Why another release is needed

Published 8.0.11 passed its release workflow, but an actual managed update
failed with `revision: lifecycle journal budget exceeded`. The downloaded
binary exceeded the old installation-journal allowance. The update did not
complete: the old 8.0.10 manifest remained at revision 5, and all four owned
file hashes still matched it. The published 8.0.11 artifacts are immutable.

The [repair architecture](../architecture-8.0.12.md) explains the bounded
schema-1 journal changes. The proposed limits are 32 MiB per file and 64 MiB
for the aggregate journal; package validation, ownership, rollback, and
unknown-file preservation remain required. No background agent service or new
host hook is introduced.

## Required evidence

1. Test the committed installer with measured executable sizes around 14 MiB
   on both sides of an update. Cover successful update, recovery, rollback,
   oversized rejection, and preservation of modified or unknown files.
2. Run native tests and vet on the required platform matrix. Verify current
   version authority, host skill metadata, release manifest, and SBOM.
3. Build the actual release artifact and run its managed-update canary against
   a prior installation. Small synthetic binaries alone do not qualify this
   repair. Verify the resulting installed manifest and exact owned hashes.
4. Verify archive checksums, Windows bundle layout, readiness, rollback, and
   provider evidence against the release revision before publishing.
5. After publication, download and verify the assets again, complete the
   separately authorized managed update, and rerun setup/status smoke checks
   against the installed controller. Only then update current-release Pages
   and installation claims.

## Existing evidence and limits

The [8.0.11 release record](8.0.11-readiness.md) preserves its successful
publication and subsequent update failure. Packaged 8.0.11 smoke checks passed
fresh TASKS.md setup, model migration, replay, both-host empty starts, a 64 MiB
fake Dolt store, and preservation of leftover TASKS.md. Those checks exercised
the downloaded package; they do not establish a successful managed installation.

The [first-use validation report](../first-use-ux-validation.md) preserves
earlier dependency and host-flow evidence. Its original upstream fixture was
archived under the operator's local validation directory after temporary-space
cleanup. No live Claude UI wizard test or universal model availability is claimed.

## Prospective distribution

Planned assets are `agent-teamctl-8.0.12.zip`, `RELEASE.json`, `SBOM.cdx.json`,
`SHA256SUMS`, and `agent-teamctl-8.0.12-windows-amd64.zip` with its `.sha256`
sidecar. These names do not establish publication or download availability.

Use the new controller from the complete verified distribution for
`update --version 8.0.12 --json`; the old installed controller cannot decode
the newer release metadata. Preserve manifest-recorded host locations and
retain rollback information. The skill then resolves the installed controller
by PATH or the manifest's absolute binary path.
