# Agent-Team 8.0.0 release readiness

Status: candidate; publication is not authorized or claimed by this document. The manual `vnext-release` workflow binds every result below to the checkout revision and must finish before it creates the non-force `v8.0.0` tag or GitHub release. The only deployment targets are the installed Agent-Team skill package and that GitHub release—there is no package registry or production service.

## Required sequence and commands

1. Review records: run the Phase 1–5 package tests and write `phase1-review.json` through `phase5-review.json`, each with the exact `${GITHUB_SHA}` and `Passed:true`.
2. Native matrix: run `go test ./... -count=1` and `go vet ./...` on Linux, macOS, and Windows.
3. Benchmark: run `go test -json ./internal/bench` and retain all raw pointers described in [the benchmark report](../benchmarks/vnext-optional-8.0.0.md).
4. Package: run `go run ./cmd/vnext-release package --version 8.0.0 --commit "${GITHUB_SHA}"`; verify `SHA256SUMS`, `RELEASE.json`, the deterministic ZIP, and native CycloneDX `SBOM.cdx.json`.
5. Canaries: run the exact packaged archive through `TestCodexCanary`, `TestClaudeCanary`, `TestPackagedArchiveCanary`, and `TestCutover`.
6. Rollback: run `TestBothHostsRollbackAndActions` and re-hash every restored manifest-owned file while confirming unrelated host settings remain byte-identical.
7. Provider: run `TestProviderVerification` only against the pre-authorized non-production staging profile. Production targets remain rejected.
8. Installed skill: require a passing packaged-archive canary for both Codex and Claude.
9. Finalize: run `finalize-evidence`, `write-readiness`, then `verify-gates --evidence release-evidence/release-readiness.json --revision "${GITHUB_SHA}"`.
10. Publication, only after explicit authority: fetch tags, prove `v8.0.0` is absent, create the annotated tag, use non-force `git push origin v8.0.0`, and create the GitHub release from the four verified outputs.

## Evidence and digests

The workflow records SHA-256 digests rather than editable success flags for benchmark, artifact manifest, SBOM, canary, rollback, provider, and installed-skill evidence. `release-readiness.json` also binds all five independent review records and every gate to the release commit. Actual digests are generated from the candidate bytes; this source document intentionally contains no precomputed or stale digest.

## Migration, rollback, and limitations

- v7.3.1 and `TASKS.md` are legacy provenance. Migration copies no lease, worker, hook, credential, MCP value, or authority.
- Codex and Claude canaries are independent foreground observations; switching hosts transfers no process or lease.
- Rollback deletes or restores only checksum-matching owned bytes and retains changed or unknown paths.
- The dashboard is local-only. Optional-tool token counters may be unavailable and are reported as unknown with zero estimated delta.
- No hook registration, MCP registration, package registry, force push, main-branch push, or production-service deployment is part of this candidate implementation.
