# Agent-Team 8.0.11 release readiness

Version 8.0.11 is an **unpublished candidate** for native first-use setup and
host dispatch. Linux amd64 and Windows amd64 are the intended package targets;
macOS remains a source/runtime verification target. This document defines gates,
not evidence that the candidate passed or that assets are available. Historical
8.0.10 publication facts remain in its own readiness document and changelog.

The [architecture changes](../architecture-8.0.11.md) explain the source
boundaries and persistent state behind these behaviors.

## Candidate behavior

- Discover the installed controller without assuming PATH and expose both native
  skills at `agent-team/SKILL.md`. Update, rollback, and uninstall preserve exact
  ownership while reconciling historical nested and manually moved entrypoints.
- Inspect and reuse the selected Beads or TASKS.md tracker, request consent for
  missing artifacts and dependency preparation, and preserve refused setup.
- Support nested Project Kickoff 0.5.0/0.5.1 handoffs, dependency preparation before
  planning, and approved late attachment without resetting existing authority.
- Save independent model/effort preferences for both hosts' orchestrator,
  developer, reviewer, and visual reviewer roles. Explicitly save accepted
  inherited defaults; never claim a preference switches the current parent.
- Use actual host tools and exact returned handles for Codex and Claude. Observe
  foreign or uncertain existing launches without duplication. Require actual
  completion, independent CLEAN review, and idle evidence before retained reuse.
- Prepare selected dependencies and prerequisites in project scope without
  external hooks, global PATH edits, or registry changes. Report missing required
  capabilities and no-ready-task states without fabricating readiness.
- Bind linked Go dependency provenance to the checksum-verified executable and
  include actual module versions and Go sums in the native SBOM.
- Preserve explicit inheritance and custom model settings while normalizing only
  the documented exact legacy IDs. Native host metadata determines actual model
  support; saved preferences alone do not establish availability.

## Local validation scope

The [validation report](../first-use-ux-validation.md) records a passing full Go
test/vet run, focused model race checks, documentation checks, and all 26 artifact
checks for the candidate worktree on base `b376fdc`. Those local checks are
pre-commit evidence. Final numbered-picker prose passed its documentation
check and pressure review; the prior artifact run retains its stated scope because package schema,
paths, contract and implementation are unchanged. CI must still verify the
committed candidate and its exact release artifacts on the required platforms.

## Revision-bound publication gates

1. Commit the final source and version authority together. Run the required full
   native test/vet matrix and relevant documentation/artifact checks on that exact
   revision; prior candidate results do not qualify later changes.
2. Use `.github/workflows/vnext-release.yml` with version `8.0.11`. It dispatches
   explicit platform checks and phase evidence before packaging. The release CLI
   version/revision are injected at build time; a development build's
   `0.0.0-dev` output is not a published binary.
3. Build deterministic Linux and Windows distributions with matching VERSION,
   WORKER-CONTRACT, host skill metadata, release manifest, native SBOM, and
   checksums. Verify SBOM module provenance against the same packaged executable,
   including its linked YAML module. Do not commit generated executables or
   release archives.
4. Require the packaged Windows canary and native canary/rollback evidence on the
   candidate revision. The Windows bundle gate checks both host root SKILL.md
   files, their exact manifest paths/hashes/sizes, and absence of nested duplicates.
   Exercise fresh setup and existing-install update, including
   ownership-preserving entrypoint migration, settings, and real host dispatch
   where the host is available. Label fixture and build checks separately from
   observed host execution.
5. Verify the workflow's readiness document, phase checks, canaries, rollback,
   and provider verification against the exact revision before publication.
   The authorized publish job creates the version tag and GitHub release assets;
   a local build or this document never substitutes for those gates.
6. After publication, verify downloaded assets/checksums and live Pages, then
   update candidate labels only to the state actually observed. Perform any
   separately authorized managed update using the verified distribution and
   its new controller with the existing install manifest, retaining rollback and
   changed/unknown files. The old controller's strict release decoder cannot read
   the new Go module field; do not use it to parse the new distribution.

The intended assets are `agent-teamctl-8.0.11.zip`, `RELEASE.json`,
`SBOM.cdx.json`, `SHA256SUMS`, and the separate
`agent-teamctl-8.0.11-windows-amd64.zip` bundle plus its `.sha256` sidecar.
Their names are prospective until the authorized release completes. No live
installation, release publication, or disconnected Windows execution is claimed.
