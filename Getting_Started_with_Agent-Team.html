Before you begin: Project Kickoff and Agent-Team are skills, not terminal programs. The blocks below are messages to paste into Codex or Claude Code. They are not Bash commands.

01Prepare GitHub accessInstall Git and GitHub CLI, sign in safely, then verify private-repository access.

You need Codex or Claude Code, Git, GitHub CLI (gh), a browser, and a GitHub account that can read the private Project Kickoff and Agent-Team repositories. Node.js 24 is needed only for lifecycle hooks.

You provide

GitHub repository access, browser approval, host sign-in, model access, and approval for machine changes.

Your agent can do

Inspect software, explain an installation plan, install approved tools, configure Git, and verify access without showing secrets.

Prompt • requires GitHub CLI and a browser
Check whether Git, GitHub CLI (gh), and Node.js 24 are available. Do not change anything yet. Report what is missing, the official installation method for this operating system, and every file or setting it would change.

I need access to the private repositories https://github.com/thebpandey/project-kickoff and https://github.com/thebpandey/agent-team. If gh is missing, ask my permission before installing it. If it is not authenticated, guide me through browser-based GitHub sign-in. Do not ask me to paste a password, token, or secret into chat. Configure Git to use this account, then verify read access to both repositories. Stop and explain any access error.
Browser sign-in is yours to complete. Open the URL or enter the device code shown by GitHub CLI. The normal flow uses the system credential store when available. Installing gh does not give an account access to a private repository.
02Install and run Project Kickoff firstDefine the product and implementation plan before Agent-Team delegates the work.

Project Kickoff guides a new project, audits an existing project, or replans a major revision. It moves through discovery, approved planning, setup, and handoff. It asks one unresolved question at a time, creates approved product, design, and technical planning records, and prepares an Agent-Team handoff. It does not implement product features or start Agent-Team by itself.

Install it in the project you are planning. Project Kickoff is project-local: use .agents/skills/project-kickoff for Codex or .claude/skills/project-kickoff for Claude Code. Complete GitHub access first. You also need permission from the Skill owner to use its private repository.

Start a kickoff, then hand off

Reference commands • requires Project Kickoff
Codex:  $project-kickoff start <your project idea>
Claude: /project-kickoff start <your project idea>

Existing project: $project-kickoff audit <path>
Read-only audit:  $project-kickoff audit-only <path>
Continue later:   $project-kickoff resume <path>
Check progress:   $project-kickoff status <path>

During kickoff, approve each planning stage before the next begins. After its planning and setup phases, Project Kickoff selects one tracker, seeds the approved plan, prepares the exact $agent-team start or /agent-team start handoff, and stops. Continue with Agent-Team in step 07 only when you are ready to delegate implementation.

Optional Project Kickoff hooks: installation does not activate them. They need separate project approval, normal /hooks trust review, and Python 3.9 or later on Linux, macOS, or WSL. Keep the instruction-based workflow if those requirements are not met.

04Reload, inspect, and trust hooksHook installation and hook trust are separate actions. You make the trust decision.

Close and reopen your host after the first install or an update. Then inspect the registered lifecycle hooks. Hooks add small checks, reminders, and recovery checkpoints. They do not replace review.

Prompt • requires the bundled Agent-Team hooks
Open /hooks and show me the Agent-Team lifecycle hooks that were registered. Explain what each group does and whether the host reports it as trusted. Do not modify or approve hooks for me.
Trust is a native host action. Review the paths the host shows. If you decide to trust all currently registered hooks, choose Trust all in the host’s own confirmation screen. An agent must not approve hooks for you.
Reference command • Agent-Team
Codex:  $agent-team help
Claude: /agent-team help
05Run setup and choose dependenciesSetup checks tools, requests permission one dependency at a time, then opens settings.

Run setup in the project where you want Agent-Team to work. It checks the host, project, installed skills, and saved setup record. It never gets blanket permission to install tools.

Reference command • Agent-Team
Codex:  $agent-team setup
Claude: /agent-team setup
Prompt • references dependencies listed below
Run Agent-Team setup for this project. Check each dependency first. For every missing item, explain what it does, whether Agent-Team can install it automatically, its source and version, its scope, every file or configuration it would change, and whether it needs a separate approval. Ask me one dependency at a time. Do not install anything until I choose the displayed installation option. After dependency setup, continue to the complete settings wizard.

06Configure or change project settingsSettings apply to future starts in this project. They do not change a run already in progress.

Setup opens the complete settings wizard automatically. It asks one question at a time. Keep the defaults for the first run unless you have a specific reason to change them.

Prompt • requires Agent-Team
Run Agent-Team settings for this project. Show the current effective values and their sources. Walk me through each setting one at a time, including every role’s model and effort. Keep the current value unless I explicitly select a replacement. Save only after showing me the final summary.
07Start development with Agent-TeamUse Project Kickoff's approved handoff or another recorded task, then begin with one safe team.

A bare start selects one ready task from Beads or .agent-team/TASKS.md. A named start selects one existing task. For a new feature, ask Agent-Team to reconcile the work before it starts.

New-feature prompt • requires Agent-Team and its selected tracker
Use Agent-Team for this feature: <describe the feature, acceptance criteria, constraints, and affected project>. First check for duplicate or unfinished work. Create or reconcile the canonical task, show me the selected tracker and effective run settings, then start one team. Keep continuous mode and auto-deploy off for this first run. Verify the result and report every requirement as implemented, verified, deferred, or blocked. Do not deploy.
Existing-task prompt • requires Agent-Team
Start Agent-Team on the existing task named <task name>. Use one team, do not use continuous mode or auto-deploy, and show me the effective run settings before work begins.
