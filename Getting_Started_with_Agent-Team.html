01Prepare GitHub accessInstall Git and GitHub CLI, sign in safely, then verify required repository access.

You need a signed-in Codex or Claude Code installation with suitable model access, Git, GitHub CLI (gh), a browser, and Node.js 24 for Agent-Team's helpers and hooks. Both skill repositories are publicly visible at the time of this guide, but visibility does not grant permission under their licenses. You also need GitHub access to the project you will work on.

You provide

GitHub repository access, browser approval, host sign-in, model access, and approval for machine changes.

Your agent can do

Inspect software, explain an installation plan, install approved tools, configure Git, and verify access without showing secrets.

02Install and run Project Kickoff firstDefine the product and implementation plan before Agent-Team delegates the work.

Project Kickoff guides a new project, audits an existing project, or replans a major revision. It moves through discovery, approved planning, setup, and handoff. It asks one unresolved question at a time, creates approved product, design, and technical planning records, and prepares an Agent-Team handoff. It does not implement product features or start Agent-Team by itself.

Recommended, not required by Agent-Team. Install Project Kickoff in the project you are planning: .agents/skills/project-kickoff for Codex or .claude/skills/project-kickoff for Claude Code. Its proprietary license requires the owner's permission even if you can view the repository. Keep the complete skill package out of your application's commits. If you already have an approved plan, skip to Agent-Team and ask it to adopt that plan.

During kickoff, answer one question at a time and approve each planning stage. It creates approved product, design and implementation records, then prepares only the agreed scaffold. Close and reopen your host after the first install or an update. Then inspect the registered lifecycle hooks. Hooks add small checks, reminders, and recovery checkpoints. They do not replace review.

Explain the Agent-Team hooks registered from https://github.com/thebpandey/agent-team/tree/main/hooks, their paths, and any supported health evidence. I will open the native /hooks screen to review trust. Do not change trust settings, approve unknown hooks, or claim an unobserved event has passed.

05Run setup onceReuse your plan and tracker. Prepare missing tools in the right order.

Run setup in your project's canonical checkout. Agent-Team can reuse Project Kickoff, adopt an existing approved plan, or start from a task you define directly. Project Kickoff is never a prerequisite.

Chat commands • Agent-Team
Codex:  $agent-team setup
Claude: /agent-team setup

What happens automatically

Setup reuses compatible tools, shows a short grouped preparation summary, and installs missing mandatory and selected default components within the approved scope. It verifies useful operations before marking capabilities ready. It does not ask you to approve each already-selected plugin again.

The agent first saves your approved plan, real project owner and selected tracker together. Existing task IDs and the integration branch are preserved. That creates the project records; it does not mean browser tools, native hooks or fresh-agent discovery have passed. Setup reports those checks separately and tells you exactly what remains.

A bare start selects one ready task from your chosen Beads or Markdown tracker. A named start selects an existing task. Independent teams use separate worktrees; review, integration and safe cleanup remain coordinated.

08See the whole project in a webpageOptional, local, read-only. Teams, progress, all tasks, and dependencies.

The dashboard complements Agent-Team status. It shows overall task-count progress, current teams and roles, and a dedicated searchable list of all tasks with statuses, owners, priorities and dependencies—not just tasks currently assigned to agents.

Saved HTML · simplest

Open .agent-team/dashboard/index.html in the canonical project. When automatic snapshots are enabled, Agent-Team refreshes the file after meaningful task transitions. Reloading reads that saved version; it cannot execute tools or query Beads. No server is required.

Live refresh · opt-in

A small Node helper listens only on your machine. Opening the page or selecting Refresh obtains current records. No build/dev framework, cloud database, task controls or public hosting is involved.

Dashboard prompt • Agent-Team, optional beads_viewer
Enable Agent-Team's local HTML dashboard for this project using https://github.com/thebpandey/agent-team. Show overall progress, current teams and all tasks with statuses. Start with saved-snapshot mode and tell me the file path. Do not start a server or publish project data.

If I select the Beads graph provider, use the separately referenced https://github.com/Dicklesworthstone/beads_viewer by Jeffrey Emanuel and first show its complete license: https://github.com/Dicklesworthstone/beads_viewer/blob/main/LICENSE. Refresh the export from my actual Beads database before generating its graph. Keep the normal task/status view available if the optional provider is unavailable.
Know what is current. Check the source and refresh time. Missing or failed reads are unknown/stale, not zero completed tasks. Cancelled and approved-deferred tasks are separated; summary parents and children are not double-counted. A task percentage is not an estimate of effort. Recorded agent activity is not proof that an agent is still running.

09Continue with less repetitionDurable checkpoints protect decisions; independent work continues around real blockers.

Agent-Team records task ownership, decisions, evidence, pending operations and the next action as work happens. A replacement agent reads a compact task packet linked to the original records. It does not rely on a chain of summaries or reload the entire conversation.

Ordinary test, lint and review findings are repaired within the approved task. If credentials, authority or an external dependency genuinely prevent progress, the orchestrator can safely park that task, retain its claim and worktree, and use released compute for another eligible task. Unknown writer liveness does not free a slot. Your explicit Pause stays in force until you resume.

Resume prompt • Agent-Team
Resume Agent-Team for this project. Restore the selected tracker, original approved and rejected decisions, ownership, exact revision, verification evidence and next action. Reconcile any pending or uncertain external operation before retrying it. Respect explicit pauses. Continue the already-authorized implementation and repair ordinary findings automatically.
Compaction is a fallback, not disabled. Small assignments and durable source-linked checkpoints reduce pressure and repeated context. They cannot guarantee zero compactions, eliminate all startup cost, or automatically replace the parent session after the host exits. Usage reports separate input, cached input, output, repair and time data; missing host/worker measurements remain unknown, with no invented savings.
