# Optional frontend resources by project type

Reviewed 2026-09-04 against upstream documentation and skill sources. These are conditional capabilities, not mandatory dependencies or equivalent kinds of tools. Prefer existing project solutions. Use an optional resource only when available, compatible, and useful for a concrete task. Missing optional resources must not block ordinary delivery. Do not install whole catalogs, enable paid services, or add global hooks automatically.

## Selection table

| Resource | Use for | Skip when | Availability boundary |
| --- | --- | --- | --- |
| [Motion](https://motion.dev/) | Product interactions, layout transitions, gestures, or purposeful scroll animation in supported web stacks | CSS already suffices; project already has a suitable animation library; no motion requirement | MIT core; AI Kit, Motion UI, and premium content are separate Motion+ offerings; use only with existing entitled access |
| [Taste Skill](https://www.tasteskill.dev/) | Distinctive landing pages, portfolios, editorial surfaces, or substantial visual redesigns needing additional art direction | Routine component fixes, dashboards, data tables, multi-step product flows, or Impeccable already resolves the brief | MIT repository; general skill is `design-taste-frontend`; current v2 is experimental and large, so inspect/pin the selected revision and load only for a justified design task |
| [img2threejs](https://github.com/img2threejs/img2threejs) | Reference-image reconstruction for interactive product objects, educational 3D, procedural props, or specialized Three.js scenes | Ordinary interfaces, generic decoration, or an existing model/image meets the need | Apache-2.0; needs suitable reference imagery, Three.js/browser rendering and supporting tooling; approximation rather than guaranteed exact geometry |
| [Awesome DESIGN.md](https://github.com/VoltAgent/awesome-design-md) | Bootstrapping coherent visual direction when a suitable reference is needed; learning token/layout patterns | An approved design system already exists or no matching reference is relevant | MIT collection of design analyses; reference material, not a runnable skill or a license to reuse third-party brand assets |
| [Bklit UI](https://github.com/bklit/bklit-ui) | Analytics, KPI dashboards, time series, and data-rich React/shadcn applications | No chart need; incompatible stack; existing chart library meets requirements | MIT chart components; Studio is proprietary. Optional published skill: `bklit-ui` |

## Apply without inflating the workflow

- Use Impeccable when available and enabled for UI/UX; otherwise follow the built-in UI workflow without blocking. Assign any additional resource a specific gap: art direction, reference tokens, charts, motion, or 3D. Record selected resource/version and purpose once in the task. Let teammates consume the resulting canonical design decisions rather than repeat discovery.
- Use no more than one extra broad aesthetic skill for a design task unless another unresolved requirement justifies it. Component-specific skills may accompany selected components. Do not start parallel Impeccable/Taste/Pro Max review cycles. User requirements, approved branding, accessibility, and actual acceptance criteria control output.
- For Taste, choose the general skill only for its documented surface types. Its source is about 1,200 lines, so never load it for every teammate by default. Do not automatically select the GPT-specific `gpt-taste` variant: its forced GSAP effects, marketing structure, and simulated randomization conflict with this harness's scope and efficiency goals. Never claim an unexecuted script ran. Do not add themes, animation, or redesign scope merely because a generic rule suggests them. [General skill](https://github.com/Leonxlnx/taste-skill/blob/main/skills/taste-skill/SKILL.md), [GPT variant](https://github.com/Leonxlnx/taste-skill/blob/main/skills/gpt-tasteskill/SKILL.md).
- For DESIGN.md references, inspect only one or two relevant examples. Adapt useful patterns into the project's canonical design specification; preserve attribution and original brand identity. Do not copy the whole catalog, overwrite approved design docs, or assume the examples are official brand specifications.
- For Bklit, load its [published skill](https://bklit.com/docs/skills) only for relevant chart work. Inspect the project's shadcn configuration, reuse installed chart types, and add only needed components. Retain correct scales/units, readable labels, keyboard/touch access or equivalent textual data, and reduced motion where relevant. Do not import its contributor-only Studio/ship workflows. The [repository license split](https://github.com/bklit/bklit-ui#license) excludes Studio from the MIT component grant.
- For img2threejs, define scope and acceptable fidelity before starting. Honor its deterministic local state gates and correction limits; do not restart state to evade a hard stop. Link its reconstruction state/artifacts from the active tracker: tool-local generation state may coexist with Beads or TASKS.md, while the selected tracker remains the project task authority. Preserve those artifacts for resumption. Validate the real browser render and representative device performance; use a static fallback when appropriate. Do not create its own extra judge/panel roles. [Skill workflow](https://github.com/img2threejs/img2threejs/blob/main/SKILL.md).
- For Motion, prefer CSS for simple effects and reuse an installed motion library. Use the current APIs for the installed version, ensure purposeful movement and reduced-motion behavior, and avoid scroll interception unless explicitly justified by the experience. The [product page](https://motion.dev/) distinguishes the free library from Motion+.

All optional verification stays within the existing focused development/review process. Stop after acceptance criteria and concrete findings are resolved.
